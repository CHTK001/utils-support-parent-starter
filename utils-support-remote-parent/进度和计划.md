# 远控网关：进度与计划

> 更新时间：2026-09-07 · 版本 4.0.0.42 · 仓库 `utils-support-parent-starter/utils-support-remote-parent`

## 一、总体架构

```
utils-support-remote-parent
├── utils-support-remote-protocol     // 信令/帧/能力模型/SPI（AgentType 三模式、Session.agentType、NegotiatedCodec.targetEncoding）
├── utils-support-remote-core         // 零拷贝传输（FrameServer/FrameClient/FrameCodec 二进制帧、RemoteTransport/RemoteFlow/RemoteServer/Client）
├── utils-support-remote-gateway      // 网关核心：信令 + 转码（GatewayServer、AuthManager、SessionManager、RouteManager、TranscodeEngine+GatewayTranscoder）
├── utils-support-remote-agent        // 被控端（三模式：FORWARD 纯转发 / SHELL 套壳自启 freerdp 或自研 / PUSH 纯自研实时推送仅监控）
└── utils-support-remote-controller   // 控制端（仅 Web + Java 套 Web 壳；ControllerClient、DecoderRenderer、InputInjector）
```

**控制端架构约束**（用户确认）：
- 控制端只有两种形态：**Web 浏览器** 和 **Java 套 Web 壳**（内嵌 Web 服务器）
- 控制端协议：
  - **SSH 走 WebSocket**：SSH 命令通过 WebSocket 传输到 agent 执行
  - **远程桌面走 WebRTC**：RDP 视频流通过 WebRTC 传输
- 控制端输入：账号密码（自研的不需要显示）、agentID（含 ip、端口）、验证码、ip、端口等
- SSH 支持开启反向隧道（agent 在 NAT 后时）

**Agent 三模式**（用户确认）：
| 模式 | 能力来源 | 说明 |
|---|---|---|
| FORWARD | 三方软件（freerdp/vnc/ssh） | 被控端仅做会话桥接转发 |
| SHELL | 自启 freerdp+转发，或自研 | Java 启动器套壳 |
| PUSH | 纯自研 | 实时画面推送，**仅监控无远程控制**（控制端已实现禁控守卫） |

**编解码协商规则**（用户确认，TranscodeEngine 已实现）：
1. 被控端编码优先：按**被控端**编码列表顺序找与控制端解码能力的交集（如默认 `h264` 优先、`jpeg` 兜底）
2. 交集为空（都不一致）→ **网关转码**：源=被控端第一个编码，目标=控制端第一个支持编码（`transcoded=true`，`GatewayTranscoder.transcode` 兜底执行）
3. 服务端不额外推 JPEG/不做无关转码——一致时帧原样透传

**单向连通场景**（用户确认：agent 无法被网关主动连接）：
- 典型 NAT 场景：agent 能出连网关，网关不能入连 agent
- 解决方案：控制端参数通知网关是否启用反向隧道
- 控制端在会话建立时通知网关 `reverseTunnelEnabled=true`
- 网关启用后，agent 主动创建 **SSH 反向隧道**到网关（`SshClient.TunnelDefinition.remote()`）
- 网关通过反向隧道的本地端口反向访问 agent
- agent 注册时 `AgentInfo.extra` 上报 `reverseTunnelPort`/`gatewayLocalPort`
- 网关读取该信息后通过本地端口连接 agent

**网关核心职责**（用户确认）：
- **信令**：agent/controller 注册、鉴权（验证码/令牌）、会话管理、消息路由、编解码协商
- **转码**：编解码能力交集为空时，网关执行 h264↔jpeg 转码
- **连接策略**：一个请求一个连接，不复用连接，提高吞吐
- 网关不关心具体业务逻辑，只负责信令转发和编解码适配

**单端连通处理流程**：
1. 控制端输入参数（agentID、账号密码、验证码、reverseTunnelEnabled、连接方式），隐藏参数含自身解码器支持
2. 根据 agentID 判断可用连接方式（如 Win 不显示 SSH）
3. 控制端先 HTTP 验证网关（所有参数校验），失败→提示错误；成功→创建 WebSocket（SSH）和 WebRTC（桌面）连接
4. 网关创建会话，保存请求参数
5. Agent 向网关注册（能力、编码集、平台信息）
6. 网关编解码协商：取控制端解码能力与被控端编码能力的交集
7. 网关开始转发：
   - **SSH 方式**：SSH 指令 → 控制端 WebSocket → 网关 → Agent
   - **远程桌面方式1**：RDP 帧 → 控制端 WebSocket → 网关 → Agent（freerdp, rdp）
   - **远程桌面方式2**：Agent（自研 push）→ 网关 → 控制端 WebSocket
8. **网关策略**：一请求一连接，不复用连接，提高吞吐
9. **reverseTunnelEnabled=true**：会话创建时 Agent 主动创建反向 SSH 隧道到网关（`SshClient.TunnelDefinition.remote()`），网关通过该端口反向访问 agent

## 二、当前进度（已完成并验证）

### 1. 零拷贝传输层（remote-core）✅
- 二进制定长前缀帧：`totalLen|type|sidLen|metaLen|payloadLen|sessionId|meta(json)|payload`，**无 buffered 流、无 Base64、无字符串中转**
- 写路径 gather（payload `ByteBuffer.wrap` 零复制）；读路径 payload 直读目标 byte[]
- `FrameServer`/`FrameClient`：NIO 阻塞通道 + 虚拟线程一连接一线程；hello 握手（首帧 CTRL+meta{kind:hello, clientId}）注册连接身份，`connect()` 同步等 ack
- `RemoteTransport`/`RemoteFlow` API不变换底座；连接标识=定向路由键（控制端传接入令牌）
- 修复：readBinary 跳长度字段误用 1 字节 → 字段错位、读线程静默死亡（虚拟线程任务须兜底 catch Exception）
- 修复：`FrameServer.closeQuietly(SocketChannel)` 缺失 → 添加静态 helper；`FrameCodec.writeBinary` 参数从 `WritableByteChannel` 改为 `GatheringByteChannel`（`SocketChannel` 实现此接口，支持 `write(ByteBuffer[])` gather 写）

### 2. 控制端 Java 侧（remote-controller）✅
- `ControllerClient`：以接入令牌注册连接、信令上报 ControllerInfo、startSession（预生成 sessionId + Session 信令携带 verifyCode 元数据）、closeSession、sessionEstablished、PUSH 会话拒绝键鼠注入
- `DecoderRenderer`：热路径仅解码一次（1080p 162ms→33ms/帧），`setFrameListener` 交付嵌入方绘制；缩略图由解码结果缩放
- 冒烟 `RemoteCoreControllerSmokeTest` **11/11**（含 256KB 大帧字节级一致）

### 3. 网关与协议 ✅
- 鉴权模型：agentRegister 首次注册登记验证码（重复注册校验一致性）；controllerConnect 令牌即凭据首次接入注册；createSession 校验被控端验证码
- handleSignal 按 kind 元数据分发 AgentInfo/ControllerInfo 注册信令；CTRL 帧按会话→agentId 定向路由
- Session 携带 agentType；NegotiatedCodec 含 encoding/targetEncoding/width/height/quality/transcoded

### 4. 性能基准（RemotePerfBenchmark）
- 编解码：二进制 1015~2577 MB/s vs JSON+Base64 66~79 MB/s（**16~40x**）；线上体积省 ~36%

## 三、控制端架构约束（用户确认）

- 控制端只有 **Web 浏览器** 和 **Java 套 Web 壳**（内嵌 Web 服务器）两种形态
- 控制端协议：
  - **SSH 走 WebSocket**：SSH 命令通过 WebSocket 传输（信令通道）
  - **远程桌面走 WebRTC**：RDP 视频流通过 WebRTC 传输（媒体通道）
- 控制端输入项：账号密码（自研不需要显示）、agentID（含 ip、端口）、验证码、ip、端口等
- SSH 支持开启反向隧道（agent 在 NAT 后时，agent 主动创建反向隧道到网关）
- **网关核心 = 信令 + 转码**：网关只做信令路由和编解码转码，不关心业务逻辑
- **网关双协议**：TCP（agent/Java控制端）+ WebSocket（浏览器），WS端口 = TCP端口 + 2
