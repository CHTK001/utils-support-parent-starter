三、累计修复的源码缺陷

#缺陷修复
1周期任务取消失效：重排每次 new 新实例，cancel 只标记旧引用，轮内活跃的新实例继续无限循环重排复用同一 TimerTask 实例（包级 advanceDeadline() 推进 volatile deadline），取消状态随实例传播
2Error 杀死时间轮：TimerTask.run 只捕获 Exception，Error 穿透终止 tick 线程，全部后续任务永不执行提交侧 Throwable 兜底 + 双层安全日志（SLF4J 失败降级 stderr）
3关闭延迟 + 静默拒绝：shutdown 仅置位不中断（最长延迟一个 tick）；schedule(Runnable) 在关闭后被静默丢弃仍返回非 null 句柄持有 tickThread 引用并在 shutdown 时 interrupt 立即退出；工厂方法调度失败返回 null（接口 Javadoc 同步）
4slotDistance 公式缺陷：delay/tick+1 多余保守量使首触必迟一拍；执行漂移后 delay≤0 归零挂回当前槽，周期任务等整圈(≈3.2s)才再次扫描改 ceil 向上取整精确落位；delay≤0 取最小偏移 1 下个 tick 补触发
5cancel 竞态：runningFuture 在 submit 之后赋值，虚拟线程可能先于赋值启动，cancel 读到 null 导致中断丢失手工构造 FutureTask：先绑定 future 再入队，窗口归零

四、v2 并发语义说明

  • fixed-rate tick：tick 线程按启动时刻为基准的绝对时间轴推进，任务耗时/系统抖动不会累积漂移，落后时连续补扫追赶。
  • 任务并发执行：到期任务提交至虚拟线程执行器并发运行，慢任务不再阻塞轮子推进；不同任务无顺序保证。
  • cancel 可中断：经 FutureTask.cancel(true) 向业务线程发送中断，业务体响应中断即可即时退出（协作式）。
  • 分槽锁：注册/取消/扫描仅竞争所属槽的独立 ReentrantLock，高并发注册互不阻塞。
  • 日志故障隔离：SLF4J 输出异常时降级 stderr，绝不因日志系统故障反噬时间轮线程。

五、核心 API 形态

Timer wheel = Timer.newTimer(64, 50, TimeUnit.MILLISECONDS);

wheel.schedule(() -> doWork(), 100, TimeUnit.MILLISECONDS);          // 单次
TimerTask p = wheel.scheduleAtFixedRate(() -> beat(),                // 固定周期（fixed-rate）
        50, 100, TimeUnit.MILLISECONDS);                              // 已关闭时返回 null
wheel.cancel(p);                                                      // 取消并中断在途执行
wheel.getTickCount(); wheel.getTaskCount(); wheel.isRunning();
wheel.shutdown();                                                     // 中断 tick + 全部在途任务
