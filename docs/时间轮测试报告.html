三、本轮修复的源码缺陷

#缺陷修复
1周期任务取消失效：重排每次 new 新实例，cancel 只标记旧引用，轮内活跃的新实例继续无限循环重排复用同一 TimerTask 实例（新增包级 advanceDeadline() 推进 volatile deadline），取消状态随实例传播
2Error 杀死时间轮：TimerTask.run 只捕获 Exception，Error 穿透终止 tick 线程，全部后续任务永不执行tick 循环对单任务执行增加 Throwable 兜底 log.error
3关闭延迟 + 静默拒绝：shutdown 仅置位不中断（最长延迟一个 tick）；schedule(Runnable) 在关闭后被静默丢弃仍返回非 null 句柄持有 tickThread 引用并在 shutdown 时 interrupt 立即退出；工厂方法调度失败返回 null（接口 Javadoc 同步）

四、已知边界（设计取舍，已文档化）

  • fixed-delay 语义：tick 线程 sleep(tick) 与任务串行执行，任务耗时累积造成周期漂移（非严格 fixed-rate）。
  • 执行中不可中断：cancel/shutdown 对正在执行的 任务体不强制打断（协作式），仅阻止后续触发。
  • getTaskCount 弱一致：size 为普通 int 读，统计值为近似值。
  • 槽位锁为粗粒度单锁（工程阶段取舍），高并发注册可考虑分槽锁优化。

五、核心 API 形态

Timer wheel = Timer.newTimer(64, 50, TimeUnit.MILLISECONDS);

wheel.schedule(() -> doWork(), 100, TimeUnit.MILLISECONDS);          // 单次
TimerTask p = wheel.scheduleAtFixedRate(() -> beat(),                // 固定周期
        50, 100, TimeUnit.MILLISECONDS);                              // 已关闭时返回 null
wheel.cancel(p);                                                      // 取消（对周期任务立即生效）
wheel.getTickCount(); wheel.getTaskCount(); wheel.isRunning();
wheel.shutdown();                                                     // 中断 tick 线程立即停止
