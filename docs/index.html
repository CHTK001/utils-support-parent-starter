一、项目概述 #

utils-support-example-starter 是 utils-support-parent-starter 生态下的统一示例模块，涵盖 100+ Example 类、50 个子包，覆盖工具类、网络通信、SSH/SFTP、任务编排、时间轮、管线、并发、AI 推理、数据源、TUI 终端、SPI 扩展等 12 个功能领域。

每个 Example 类采用 全场景自检 模式：内部实现完整功能验证，通过 --type=xxx 参数选择性地运行特定场景组，输出 [PASS]/[FAIL] 标记并以退出码 0/1 结束。Benchmark 类使用 System.nanoTime() 精确计时，输出 ops/s 表格。

架构特点：SPI 插件化 + 统一入口 ExampleRunner + 独立 main() 双运行模式。所有示例无 Spring Boot 依赖（部分 Web 示例除外），轻量级可独立运行。

4.4 任务编排 (TaskRunner) #

📋

TaskRunnerExample

轻量级 DAG 任务编排全场景自检，覆盖串行/并行/完成策略/可靠性/响应式五大场景组，776 行代码，18 个测试场景。

串行依赖

TaskRunner runner = TaskRunner.newRunner();
runner.addNode("A", () -> "A done")
      .addNode("B", () -> "B done")
      .addNode("C", () -> "C done");

// afterNode: 串行链 A → B → C
runner.addNode("A", () -> "A1")
      .afterNode("B", () -> "B1")
      .afterNode("C", () -> "C1");

// dependsNode: 数据依赖 (A,B → C)
runner2.addNode("A", () -> "A")
       .addNode("B", () -> "B")
       .addNode("C", () -> "C")
       .dependsNode("C", "A", "B"); // C 等待 A,B 完成

// 执行
RunResult result = runner.execute();

完成策略

// allSuccess: 全成功 -> PASS，任一失败快速取消下游
runner.completionPolicy(CompletionPolicy.allSuccess());

// anySuccess: 任一成功即提前退出并取消剩余
runner.completionPolicy(CompletionPolicy.anySuccess());

// 成功率策略
runner.completionPolicy(CompletionPolicy.successRate(0.8));  // 80% 成功即通过
runner.completionPolicy(CompletionPolicy.successAtLeast(2)); // 至少 2 个成功
runner.completionPolicy(CompletionPolicy.failAtLeast(2));    // 最多容忍 2 个失败

可靠性与熔断

// 单任务超时隔离
runner.addNode("slow", () -> {
    Thread.sleep(5000);
    return "done";
}).timeout(Duration.ofSeconds(1)); // 超时自动取消

// 全局重试
runner.globalRetry(3); // 失败自动重试 3 次
    // 配合 RetryListener 监听重试次数

// 熔断降级
runner.failureThreshold(2)        // 连续 2 次失败触发熔断
      .circuitBreaker(true)       // 启用熔断器
      .fallback(task -> "降级结果"); // 熔断后走降级

异步与响应式

// 异步执行
CompletableFuture<RunResult> future = runner.execute();

// 取消传播
future.cancel(true); // 传播中断到正在执行的任务

// 响应式 Mono
Mono<RunResult> mono = runner.executeReactor();
mono.subscribe(result -> System.out.println("结果: " + result));

// 事件流
runner.watch().subscribe(event -> {
    switch (event.eventType()) {
        case RUN_STARTED -> log.info("运行开始");
        case NODE_STARTED -> log.info("节点 {} 开始", event.nodeId());
        case NODE_SUCCESS -> log.info("节点 {} 成功", event.nodeId());
        case NODE_FAILED  -> log.info("节点 {} 失败", event.nodeId());
        case RUN_COMPLETED -> log.info("运行完成");
    }
});

八、常见问题 #

Q: 运行时报 ClassNotFoundException？
确保先完成 mvn compile 或 mvn install。某些依赖（如 native 模块、特定模型）可能未包含在默认 classpath 中，使用 fat jar 或完整构建可以解决。
Q: --enable-preview 错误？
项目使用 Java 25 preview 特性，必须添加 --enable-preview JVM 参数。使用 Maven 时已在 pom.xml 中自动配置；直接 java 运行时需手动添加。
Q: 某些 Example 编译失败/被排除？
pom.xml 的 exec-maven-plugin 中 <exclude> 列表排除了 15 个旧示例（如 FlowTraceExample, HttpClientExample 等），确保新增 Example 时也需更新排除列表。
Q: ONNX 模型路径配置？
通过 -Donnx.model.path=/path/to/models 系统属性或 ONNX_MODEL_PATH 环境变量指定模型权重路径。模型文件从 utils-support-models-parent 模块获取。
Q: ShmQueue 测试跳过？
ShmQueue 需要 utils-support-native-parent 中的 native 实现。如需使用，先构建 native 模块并将对应的 native 库（dll/so）加入 java.library.path。
Q: 如何添加新的 Example？
1. 在对应子包下创建 Java 类，实现 main() 方法
2. 如需 SPI 注册，实现 com.chua.example.spi.Example 接口
3. 在 META-INF/extensions/com.chua.example.spi.Example 中注册 SPI
4. 更新 pom.xml 排除列表（如需要）
5. Example 类遵循 [PASS]/[FAIL] 输出约定 + 退出码 0/1
