一、测试目标

验证 FacePipeline 的入库 / 检索 1:N 闭环，重点覆盖本阶段两项改造：

  • 双检测器合并（Branch 化）：detectBoxes 以 {@Branch} 工具重构——常规模型 （yolo-face-detector，YOLOv11n 真人脸）与动漫模型（anime-face-detector，YOLOv8 v1.4_n）各自经 ofBytes → when → recover 异常降级为空后合并，跨模型 NMS 去重； 替代原先两组 try-catch + if-null 嵌套。
  • AnimeFaceDetector 阈值修复：sigmoid 激活 + 张量布局修正后的检出质量回归验证。

五、关键代码对照（detectBoxes）

// Before：两组 try-catch + if-null 嵌套（14 行样板）
List<PredictRectangle> merged = new ArrayList<>();
try {
    List<PredictRectangle> boxes = detector.detect(imageData);
    if (boxes != null) merged.addAll(boxes);
} catch (Exception e) { log.debug("常规检测失败: {}", e.getMessage()); }
if (animeDetector != null) {
    try {
        List<PredictRectangle> animeBoxes = animeDetector.detect(imageData);
        if (animeBoxes != null) merged.addAll(animeBoxes);
    } catch (Exception e) { log.debug("动漫检测失败: {}", e.getMessage()); }
}

// After：Branch 流式链 —— 异常降级为空，语义与缩进同步归零
List<PredictRectangle> regular = Branch.ofBytes(imageData)
        .when(v -> true, detector::detect)
        .recover(e -> { log.debug(...); return Collections.emptyList(); })
        .get();
if (animeDetector == null) return filterBoxes(crossNms(regular));
List<PredictRectangle> anime = Branch.ofBytes(imageData)
        .when(v -> true, animeDetector::detect)
        .recover(e -> Collections.<PredictRectangle>emptyList())
        .get();

六、过程修复记录

问题根因修复
YoloFaceTranslator 实例化失败
NoSuchMethod <init>()		仅有 DetectionConfiguration 构造器，SPI 反射要求无参构造补无参构造委托 this(null)，走默认阈值 0.85
AnimeFaceDetectorTranslator 同类失败协作会话重写后同样缺失无参构造同上补无参构造（默认 conf=0.45）
ArcFace 预处理 ClassCastException
DataBufferByte→DataBufferInt		OnnxImageProcessor 将 TYPE_4BYTE_ABGR（字节缓冲）误路由至 DataBufferInt 强转分支INT 直读白名单收紧为 INT_RGB/INT_ARGB，ABGR 字节类型落入通用 getRGB 路径
ModelRegistry 编译错误
catch ClassNotFoundException 不可达		新版 ReflectUtils.forName 吞 CNFE 返回 nullforName 返回 null 时主动抛 ClassNotFoundException，维持原异常路径

七、遗留与建议

  • yolo-face 对强动漫风图像（如 1peopleman.png）检出为 0——属模型域差异，正是保留双检测器合并的理由；后续可引入 anime-real-cls 分类器在裁剪后做逐脸域归属，替代当前 labelName 判断。
  • 仓库存在并行会话实时改写源码（本期间 ModelRegistry / OnnxImageProcessor / pom 均被外部改动），合入前建议先与对方对齐基线。
  • 当前相似度未打印具体分值，后续可在 FaceIdentifyHit 中补充 score 字段输出，便于报告量化。
