集群服务器 ClusterServer 使用说明

一行代码启动无中心化集群节点。Scatter 负责服务发现与路由决策，ClusterServer 封装为开箱即用的集群服务。

术语说明：
Scatter — 底层机制：对等网格服务发现 + 路由决策（seed 引导 / gateway 模式）
ClusterServer — 上层产品：基于 Scatter 封装的完整集群服务（HTTP/TCP 代理入口 + 自动注册）

1. 快速开始

Java API 构建

try (ClusterServer server = ClusterServer.builder()
        .scatterId("order")                              // 业务分组标识
        .seeds("192.168.1.10:19001")                      // seed 引导节点
        .addServer("/api", "192.168.1.20", 8080, "http")  // 注册 HTTP 后端
        .addServer("/pay", "10.0.0.5", 9001, "tcp")       // 注册 TCP 后端
        .master("order-master.example.com")               // 可选：主入口标记
        .build()) {
    server.start();   // 自动完成发现/注册/代理
}

Spring Boot 自动装配

3. 核心概念

层级职责关键类
Scatter服务发现 + 路由决策。对等网格，节点间通过帧协议交换服务表ScatterServiceDiscovery / ClusterManager
ClusterServer集群服务门面。在 Scatter 之上提供 HTTP/TCP 代理入口、自身自动注册ClusterServer / ClusterNode

端口分配规则

若 port 设为 8080，实际占用三个连续端口：
8080 — HTTP 业务入口  |  8081 — TCP 代理入口  |  8082 — Scatter 通信端口（port+2 自动计算）

5. ClusterServer / ClusterManager 方法

ClusterServer 对外方法

方法返回值说明
start()void启动集群节点；重复调用是 no-op
manager()ClusterManager集群管理器：路由决策、视图查询、健康检查
discovery()ScatterServiceDiscovery直接访问 scatter 发现服务

getTcpPort()int实际 TCP 代理端口

ClusterManager 方法

ClusterManager mgr = server.manager();
Set<Discovery> all = mgr.nodes("/api");                      // 全部节点
Set<Discovery> filtered = mgr.nodes("/api", "order", "http"); // 按 path+scatterId+protocol 过滤
Discovery target = mgr.route("/api", "order", "http");         // 负载均衡选目标，排除本节点
int count = mgr.healthyCount("/api", "order", "http");          // 可用节点数

6. HTTP/TCP 请求如何处理

客户端请求到达后，scatter 按以下决策链处理：先查本节点是否提供该服务，再查集群视图，最后按负载均衡策略选目标。

1

请求到达入口

HTTP 打到 port，TCP 打到 port+1

2

path 前缀匹配

按 scatterId + path 前缀查本地 hash 表

3

本节点有服务？

有 → 用权重平衡选目标（本机优先）
没有 → 返回 404

4

权重平衡策略

本机权重最高（1.0），其他节点按 cpu+mem 动态权重
默认 weight 模式：选加权最高的节点

5

本地 or 转发

选中本机 → 直接交给业务 handler
选中远端 → ReverseProxyServerFilter 代理转发

6

远端节点处理

目标节点收到后重复相同流程，返回响应

权重计算（CPU + 内存动态权重）

每个节点的动态权重 = 1.0 − (0.6 × cpu 使用率 + 0.4 × 内存使用率)，范围 [0.1, 1.0]。
本机权重固定为 1.0（最高优先级），远端节点按实时负载计算，负载越高权重越低，请求越少。
Balancer SPI 持久化：每个节点的 LoadBalance 实例由 SPI 初始化后复用， weight 衰减状态跨请求保持；服务表实际变化（节点增删）时才重建，避免每次请求都重新创建导致状态丢失。

scatter 后台同步操作

操作协议帧说明
自身注册—以 nodeId-http / nodeId-tcp 注册本节点端口
拉取服务表REQ → RESP向 seed/对等节点拉取完整服务表，合并进本地 hash
推送自身PUSH → ACK将本节点服务信息推送给 seed，扩散到集群
心跳探活REQ → RESP连续失败达阈值自动从 hash 表剔除
选举新引导ELEC → ACKseed 全掉线时，最小 nodeId 节点成为新引导

Balancer SPI 使用规则

属性说明
per-node 初始化每个节点通过 clusterSetting.setBalance() 配置自己的策略（如 weight、round），不同节点可以不同
SPI 实例持久化LoadBalance 实例按 path#scatterId#balance#protocol 缓存，服务表不变时跨请求复用，保持内部状态（如 weight 衰减）
触发即使用当前节点策略请求到达某节点时，该节点用自己的 balance 配置查服务表并选目标，不受其他节点策略影响

7. Scatter 模式

Seed 引导模式

ClusterServer.builder()
    .scatterId("order")
    .seeds("192.168.1.10:19001", "192.168.1.11:19001")
    ...

网关模式（不配 seeds 时自动启用）

不配 seeds，本节点自动成为自身网关，scatter 端口 = port+2。

// 节点一：不配 seeds，自己就是网关，scatter 端口 = 8082
ClusterServer.builder().scatterId("order").port(8080).addServer("/api", "192.168.1.20", 8080, "http").build();

// 节点二：只配置节点一的 scatter 端口即可加入
ClusterServer.builder().scatterId("order").seeds("192.168.1.10:8082").port(8090).build();

8. 典型场景

多服务路径 HTTP 集群

ClusterServer.builder()
    .scatterId("order")
    .seeds("192.168.1.10:19001")
    .addServer("/api",     "192.168.1.20", 8080, "http")
    .addServer("/api",     "192.168.1.21", 8080, "http")
    .addServer("/notify",  "192.168.1.30", 8081, "http")
    .build();

TCP 长连接代理集群

ClusterServer.builder()
    .scatterId("im")
    .httpEnabled(false)
    .addServer("/chat", "10.0.0.5", 9001, "tcp")
    .addServer("/chat", "10.0.0.6", 9001, "tcp")
    .build();

HTTP + TCP 混合服务

ClusterServer.builder()
    .scatterId("mixed")
    .addServer("/api", "192.168.1.20", 8080, "http")
    .addServer("/ws",  "192.168.1.30", 9001,  "tcp")
    .build();

9. 生命周期

builder().build()         → 创建（未启动）
server.start()            → 绑定端口 → 注册自身 → 启动 scatter → 启动 HTTP/TCP 代理
server.close()            → 等待当前轮次 → 注销自身 → 关代理 → 关 scatter

10. 注意事项

  1. seed 至少配置一个：不配时本节点自动成为网关；新节点加入需知道 seed 地址
  2. scatterId 一致性：同一业务所有节点必须相同，不同分组完全隔离
  3. 端口分配：HTTP=port，TCP=port+1，scatter=port+2
  4. 持久化恢复：scatter 默认落盘 .scatter-nodes-{nodeId}.json，重启后加速收敛
  5. master 不影响路由：所有节点在 scatter 中对等，无主从依赖
  6. addServer 混协议允许：同一 path 可注册 http 和 tcp，scatter 按 protocol 字段路由
