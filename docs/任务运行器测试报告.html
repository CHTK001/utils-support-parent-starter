五、核心 API 形态

var runner = TaskRunner.of("demo")
        .timeout(Duration.ofSeconds(10))          // 全局默认单任务超时
        .retry(3)                                  // 全局默认重试次数
        .policy(CompletionPolicy.successRate(0.8)) // 必填完成策略
        .task("a", ctx -> fetchA())
        .task("b", ctx -> merge(ctx))
            .afterNode("a")                        // 控制流依赖
            .dependsNode("a")                      // 数据依赖（前置成功即满足，允许 null 值）
            .failureThreshold(3).waitDuration(10_000)
            .circuitBreaker()                      // 熔断开关（委托 CircuitBreakerFlow）
            .fallback(ctx -> cachedValue());       // 降级兜底（不吞 Error）

runner.executeSync(input);   // 同步
runner.execute(input);       // 异步 CompletableFuture<RunResult>，cancel(true) 可中断
runner.executeReactor();     // Mono<RunResult>，完全惰性
runner.watch();              // Flux<RunnerEvent>（有界 4096，丢最旧）
runner.clearEvents();        // 重置事件窗口

六、实现要点备注

  • 调度引擎：StructuredRunnerProvider（@Spi("structured")）— Java 25 StructuredTaskScope.open(Joiner.allUntil(...)) 全图一次性 fork，节点经 CompletableFuture 等待前置就绪即执行（dataflow 就绪即跑，无层间屏障）；达标或不可能达标时提前取消剩余 fork。Provider 无共享可变状态，可支撑并发 run。
  • 单节点链路（外→内）：熔断(CircuitBreakerFlow) → 超时(嵌套 scope withTimeout 约束整个序列) → 预算感知重试(指数退避 200ms→2s 封顶；剩余时限不足以容纳下一次尝试即放弃) → 数据依赖校验 → 业务函数 → fallback 兜底（Error 因果链不降级）。
  • 被提前取消/级联跳过的节点记 SKIPPED，不计入完成策略分母；fork 体含中断检查点，取消后不再写回收集表。
  • null 返回值以内部哨兵存储：任务成功返回 null 不再误伤下游 dependsNode。
  • 异步出口 future.cancel(true) 向虚拟线程传播中断，作用域随之取消整图。
  • 熔断状态按节点 ID 跨多次 run 持久（InMemoryCircuitBreakerProvider 缓存）。
