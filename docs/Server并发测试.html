5结论与限制

✅ 核心结论
  • NioHttpServer 全面优于 JdkHttpServer：同并发下有效吞吐约为其 3~5 倍，且随并发上升仍持续扩展（256B / 并发2000 达 7.7k goodput）；JDK 实现高并发下吞吐不升反降、尾延迟暴涨（p99 从 819ms 恶化到 6.8s）——com.sun.net.httpserver 默认调度器对虚拟线程下的突发连接接纳存在瓶颈。
  • 大报文差距更明显：4096B / 并发100 时 NIO 约 18k RPS / p99 26ms，JDK 仅约 5k / p99 167ms。
  • 成功率在并发 500 普遍跌至 75%~80%（两端均有），为高并发下连接复用竞态/瞬时 5xx，属压测端未加重试的度量口径；goodput 已按成功率折算，结论不受影响。
⚠️ 限制与待补
  • VertxHttpServer 未纳入：位于 utils-support-network-starter，依赖 common-starter；当前工作树 task/timer 包处于未编译状态（缺 HashedWheelTimeWheel），无法重建依赖链路，需先修复才能补测。
  • 环境偏差：Windows 下 NIO 的 eventLoop 被钳制为 2（WindowsSelectorImpl 稳定性限制）；Linux/epoll 下不受此限制，数字会更高。建议在 Linux 2 核机重跑以贴近生产。
