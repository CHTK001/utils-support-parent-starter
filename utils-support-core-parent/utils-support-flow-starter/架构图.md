# 流程编排（Flow）架构图

> 本文档描述 `utils-support-flow-starter` 及其上层契约、领域节点、前端 ReFlow 的整体架构，涵盖模块分层、依赖关系、核心对象模型、执行时序与数据格式。

## 1. 总体架构

端到端打通「前端可视化编排 → 后端执行引擎 → 领域节点执行」，前后端以统一图格式（`FlowDefinition` JSON）为交换契约。

```mermaid
graph TB
    subgraph 前端 vue-support-parent-starter
        ReFlow["packages/reflow<br/>@vue-flow/core 封装"]
        Canvas["ReFlowCanvas<br/>画布/节点/连线/属性面板"]
    end

    subgraph 后端 utils-support-parent-starter
        subgraph L1["L1 utils-support-common-starter"]
            FlowContract["task/flow 契约<br/>Flow / FlowInstance / FlowNodeExecutor / FlowDefinition / FlowJson"]
            Pipeline["task/pipeline 执行内核<br/>Pipeline / DecisionNode / Action"]
        end
        subgraph L2["L2 utils-support-flow-starter (本模块)"]
            DefaultFlow["DefaultFlow<br/>引擎实现"]
            Engine["FlowEngine Bean<br/>节点注册表 + 执行入口"]
            Persist["流程定义/实例持久化"]
            Rest["REST Controller<br/>CRUD / 执行 / 导入导出"]
        end
        subgraph L3["L3 领域节点（自注册，可选）"]
            SpiderNode["utils-support-spider-starter<br/>@FlowNode('spider')"]
        end
    end

    Canvas -->|"FlowDefinition JSON"| Rest
    Rest --> Persist
    Rest --> Engine
    Engine --> DefaultFlow
    DefaultFlow --> Pipeline
    DefaultFlow --> FlowContract
    Pipeline --> FlowContract
    SpiderNode -. "@Extension 注册节点类型" .-> FlowContract
    Engine -. "SPI 加载节点执行器" .-> SpiderNode
    Rest -->|"节点类型清单"| Canvas
```

## 2. 模块分层与依赖关系

| 层级 | 模块 | 职责 | 依赖 |
|------|------|------|------|
| L1 | `utils-support-common-starter` | `task/flow` 契约（接口/模型/节点注册 SPI）+ `task/pipeline` 执行内核 | 无外部 |
| L2 | `utils-support-flow-starter` | 引擎实现、Spring Boot 自动装配、持久化、REST | common-starter |
| L3 | `utils-support-spider-starter` | 领域节点实现（`spider`） | 仅 common-starter |

**依赖原则（无循环）**：

```mermaid
graph LR
    flow["flow-starter (L2)"] --> common["common-starter (L1)"]
    pipeline["task/pipeline"] --> common
    flow --> pipeline
    spider["spider-starter (L3)"] --> common
    spider -. "注册节点，不反向依赖 flow-starter" .-> common
```

- 领域节点只依赖 L1 契约，**不反向依赖 flow-starter** → 任意领域模块注册节点均不破坏核心
- flow-starter 通过 SPI 发现已注册的 `@FlowNode` 执行器，运行时按节点 `type` 查找

## 3. 核心对象模型

```mermaid
classDiagram
    class Flow {
        <<interface>>
        +String getId()
        +Flow addNode(String id, String type, FlowProps props)
        +Flow addNext(String from, String to)
        +FlowInstance createInstance()
        +String exportJson()
        +Flow importJson(String json)
    }

    class FlowInstance {
        +String flowId
        +String instanceId
        +Status status  RUNNING/WAITED/COMPLETED/FAILED
        +PipelineContext context
        +FlowInstance run(Map~String,Object~ params)
        +FlowInstance resume()
        +void setAttribute(String key, Object value)
        +T getAttribute(String key)
    }

    class PipelineContext {
        +T currentData
        +Map attributes
        +List history
        +Action action
        +String nextNodeId
    }

    class FlowNodeExecutor {
        <<interface>>
        +void execute(FlowInstance instance)
    }

    class FlowNodeMetadata {
        +String type
        +String name
        +Map~String,PropSchema~ propsSchema
    }

    Flow --> FlowInstance : createInstance
    FlowInstance --> PipelineContext : 持有唯一上下文
    Flow --> FlowNodeExecutor : 按 type 查找执行器
    Flow --> FlowNodeMetadata : 供前端渲染属性面板
```

**关键设计**：`Flow`（定义，不可变、可序列化）与 `FlowInstance`（一次运行，可变、可持久化）分离；`FlowInstance` 内部**唯一持有** `PipelineContext`，是"运行必定同一个上下文"的载体。

## 4. 执行引擎桥接

`DefaultFlow` 将 `FlowDefinition` 图桥接到现有 `task/pipeline` 执行内核：

```mermaid
graph LR
    subgraph FlowDefinition
        N1["node: start"]
        N2["node: condition"]
        N3["node: httpCall"]
        E1["edge start->condition"]
        E2["edge condition->httpCall label=true"]
        E3["edge condition->end label=false"]
    end

    subgraph Pipeline
        T1["StartNode"]
        D1["DecisionNode"]
        T2["TaskNode"]
    end

    N1 --> T1
    N2 --> D1
    N3 --> T2
    E1 --> "nextNodeId 顺序推断"
    E2 --> D1.branches[true]
    E3 --> D1.branches[false]
```

- 顺序边 → pipeline 有序节点默认 next
- `condition` 节点 → `DecisionNode`（`when(true,..)/when(false,..)`）
- `TaskNode` 执行体 = 从节点注册表按 `type` 取出的 `FlowNodeExecutor`
- 挂起/恢复 → 引擎 `Action.WAIT` / `Pipeline#resume(ctx)`

## 5. 执行时序（同一上下文）

```mermaid
sequenceDiagram
    participant C as Client
    participant E as FlowEngine
    participant I as FlowInstance
    participant P as Pipeline
    participant S as SpiderNode

    C->>E: createInstance()
    E-->>C: instanceId
    C->>I: run(params1)
    I->>P: execute(ctx=新建, params1 并入)
    P->>S: spider 节点执行
    S-->>I: 结果写入 ctx.attributes/currentData
    I-->>C: status=WAITED / COMPLETED
    C->>I: run(params2) 或 resume()
    Note over I: 复用同一 ctx（同一上下文），参数合并续跑
    I->>P: resume(ctx)  挂起点继续
    P-->>I: 执行后续节点
```

**要点**：
- 每次 `run(params)` 参数合并进 `ctx.attributes`，`currentData` 可更新
- 上下文只随实例销毁，**跨多次运行不重建**
- 同一实例并发 `run` 由状态机 + 锁拦截，避免上下文竞态

## 6. 节点类型注册机制

```mermaid
graph LR
    A["@FlowNode('spider')<br/>@Extension"] --> B["SPI 索引<br/>META-INF/extensions"]
    B --> C["FlowNodeRegistry<br/>(common-starter)"]
    D["flow-starter 引擎"] -->|"按 type 查找"| C
    E["前端 /flow/node/types"] -->|"读取 FlowNodeMetadata"| C
```

注册流程：
1. 领域模块实现 `FlowNodeExecutor`，标注 `@FlowNode(type)`
2. 编译期生成 SPI 索引（复用 common-starter 的 `@Extension` 机制）
3. 运行时 `FlowNodeRegistry` 汇总全部类型 → 引擎按 `type` 实例化执行器，前端拉取类型元信息渲染属性面板

## 7. 统一图格式（FlowDefinition）

```json
{
  "id": "flow1",
  "name": "审批流程",
  "nodes": [
    { "id": "start", "type": "start",  "props": {},                   "x": 100, "y": 100 },
    { "id": "check", "type": "condition", "props": {},                "x": 300, "y": 100 },
    { "id": "end",   "type": "end",    "props": {},                   "x": 500, "y": 100 }
  ],
  "edges": [
    { "from": "start", "to": "check", "label": "" },
    { "from": "check", "to": "end",   "label": "true" }
  ]
}
```

- **导出**：`FlowDefinition` → JSON（拓扑 + 节点类型/参数 + 画布坐标）
- **导入**：JSON → 注册表查类型 → 实例化执行器 → 构建 pipeline
- `x/y` 仅供前端画布使用，后端忽略；`label` 为分支标签

## 8. 断点续跑

```mermaid
graph LR
    A["FlowInstance (WAITED)"] --> B["序列化上下文快照<br/>(ctx/currentData/attributes/history/nextNodeId)"]
    B --> C["持久化存储"]
    D["服务重启 / 外部触发"] --> E["加载实例 + 反序列化上下文"]
    E --> F["pipeline.resume(ctx)"]
```

- 挂起实例的上下文整体持久化，保证恢复后仍是同一上下文
- 异步长任务（如爬虫后台抓取）完成回调后触发 `resume`

## 9. 前端 ReFlow 架构

```mermaid
graph TD
    subgraph packages/reflow
        ReFlowCanvas["ReFlowCanvas.vue<br/>@vue-flow/core 实例"]

    end
    ReFlowCanvas --> FlowStore
    NodePanel --> ReFlowCanvas
    AttrPanel --> FlowStore
    Toolbar --> FlowStore
    FlowStore -->|"exportJson -> POST /flow"| Rest["后端 REST"]
```

- 画布操作实时反映到 `flowStore`，序列化为 `FlowDefinition` 提交后端
- 导入后端 JSON 时按 `FlowNodeMetadata` 还原节点属性表单
- 节点类型列表来自 `/flow/node/types`

## 10. 端到端流程

```mermaid
flowchart LR
    A["前端 ReFlow 拖拽编排"] --> B["导出 FlowDefinition JSON"]
    B --> C["POST /flow 保存"]
    C --> D["POST /flow/{id}/run 携带运行参数"]
    D --> E["FlowEngine 创建 FlowInstance"]
    E --> F["pipeline 顺序/分支执行节点"]
    F --> G["spider/httpCall/condition... 节点写上下文"]
    G --> H["实例完成 / 挂起等待恢复"]
    H --> I["前端展示结果 / 恢复按钮"]
    I --> D
```
