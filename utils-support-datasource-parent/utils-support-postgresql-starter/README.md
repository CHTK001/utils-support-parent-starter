# utils-support-postgresql-starter

PostgreSQL 数据库适配模块：基于 SPI 提供 `postgresql` 协议的 JDBC / R2DBC 引擎、DDL 方言、迁移脚本转换、系统表元数据操作与 pgvector 向量存储。

- **坐标**：`com.chua:utils-support-postgresql-starter:4.0.0.51`（父模块 `utils-support-datasource-parent`）
- **JDK**：25（随仓库 `maven.compiler.source/target=25`，开启 `--enable-preview`）
- **包根**：`com.chua.postgresql.support`，子包 `engine` / `ddl` / `flyway` / `meta` / `vector`
- **引入版本**：核心能力自 `4.0.0.42` 起提供，DDL Provider 自 `4.0.0.43` 起提供

## 它是什么 / 不是什么

| 它是 | 它不是 |
|---|---|
| `postgresql` 协议的 JDBC 引擎（HikariCP 连接池，默认最大 10 连接）与 R2DBC 驱动接入 | 不是连接池本身（HikariCP 由依赖带入），也不是 ORM / JPA |
| 建库 / 建表 DDL 方言：幂等建库、`CREATE TABLE IF NOT EXISTS`、`GENERATED BY DEFAULT AS IDENTITY` | 不是 Flyway 本体，只提供迁移脚本的 PostgreSQL 方言转换 |
| 基于 `information_schema` / `pg_catalog` 的表、视图、索引、触发器、存储过程、外键元数据读写 | 不提供用户 / 权限元数据与全文检索元数据（显式抛 `UnsupportedOperationException`） |
| pgvector 向量存储：原生 `vector(dim)` 列 + HNSW 索引，退化时 `double precision[]` + JVM 精算 | 不是向量数据库，也不内置 embedding 模型 |
| 通过 `META-INF/extensions` 注册的纯 SPI 模块，可被任意宿主按协议名加载 | 不提供 Spring Boot 自动配置、starter 装配或 `application.yml` 配置项 |

## 核心 API 与速查表

| 类 | 常用入口 | 用途 |
|---|---|---|
| `PostgresqlEngine` | `addDataSource(name, host, port, database, username, password)` | 注册 PostgreSQL 数据源（HikariCP，默认最大 10 连接） |
| `PostgresqlEngine` | `addDataSource(DataSourceOptions)` | 带隧道穿透的数据源注册（开隧道后改连 `127.0.0.1:隧道端口`） |
| `PostgresqlReactorEngine` | `addDataSource(...)` | 响应式入口；默认伪响应式，改传 JDBC URL 走真 R2DBC |
| `PostgresqlMetaData` | `table() / view() / index() / trigger() / procedure() / fk()` | 元数据门面，按名称或全量读取 |
| `PostgresqlMetaTable` | `list() / get() / create(name) / alter() / drop() / rename(newName)` | 表清单、表结构、建表 / 改表 / 删表 / 改名 |
| `PostgresqlDdlProvider` | `supports` 协议：`postgresql` / `postgresql9` / `postgresql10` | 幂等建库、删库、幂等建表的方言实现 |
| `PostgresqlScriptConverter` | `PROTOCOL = "postgresql"` | 把 MySQL 风格迁移脚本转换为 PostgreSQL 方言 |
| `PostgresqlVectorStorageProvider` | `toProperties(Map)` + `create(dimension, algorithm, properties, dataSource)` | 由键值配置创建 pgvector 向量存储 |
| `PostgresqlVectorStorage` | `add(id, vector)` / `search(query, topK)` / `remove` / `update` / `size` / `clear` | 向量写入、相似检索与维护 |

## 快速开始

Maven 依赖：

```xml
<dependency>
    <groupId>com.chua</groupId>
    <artifactId>utils-support-postgresql-starter</artifactId>
    <version>4.0.0.51</version>
</dependency>
```

### 1. JDBC 引擎 + 元数据

```java
import com.chua.postgresql.support.engine.PostgresqlEngine;
import com.chua.postgresql.support.meta.PostgresqlMetaData;
import com.chua.common.support.lang.datasource.table.TableDef;

// 创建引擎并注册数据源（HikariCP，默认最大连接数 10）
PostgresqlEngine engine = new PostgresqlEngine();
engine.addDataSource("default", "localhost", 5432, "testdb", "postgres", "password");

// 实体查询（与 JdbcEngine 一致的查询入口）
List<User> users = engine.query(User.class).list();

// 元数据：表 / 视图 / 索引 / 触发器 / 存储过程 / 外键
PostgresqlMetaData meta = new PostgresqlMetaData(engine);
List<TableDef> tables = meta.table().list();          // 当前 schema 全部表
TableDef user = meta.table("sys_user").get();          // 指定表结构
```

也可以不直接 `new`，走 SPI 按协议名获取：

```java
Engine engine = ServiceProvider.of(Engine.class).getExtension("postgresql");
```

### 2. 响应式引擎

```java
PostgresqlReactorEngine reactor = new PostgresqlReactorEngine();
// 伪响应式：复用同步 JDBC 引擎（boundedElastic 调度阻塞 JDBC）
reactor.addDataSource("default", "localhost", 5432, "testdb", "postgres", "password");
// 真 R2DBC（非阻塞）：用 JDBC URL 形式注册，占位符为 $n
reactor.addDataSource("r2dbc", "jdbc:postgresql://localhost:5432/testdb", "postgres", "password");
```

### 3. pgvector 向量存储

```java
import com.chua.common.support.vector.VectorCompareAlgorithm;
import com.chua.common.support.vector.VectorStorage;
import com.chua.postgresql.support.vector.PostgresqlVectorStorage;

// 直连方式：传入宿主 DataSource、向量维度与比较算法
VectorStorage storage = new PostgresqlVectorStorage(dataSource, 768, VectorCompareAlgorithm.cosine());
storage.add("doc-1", new float[]{/* 768 维 */});
List<Vector> top5 = storage.search(queryVector, 5);
```

或通过 SPI Provider + 键值配置创建：

```java
VectorStorageProvider provider = ServiceProvider.of(VectorStorageProvider.class).getExtension("postgresql");
Object props = provider.toProperties(Map.of(
        "tableName", "vector_store",
        "vectorColumn", "embedding"));
VectorStorage storage = provider.create(768, VectorCompareAlgorithm.cosine(), props, dataSource);
```

## 配置项

**本模块没有 Spring 配置项。** 依据：`src/main/resources` 下只有 5 个 `META-INF/extensions` SPI 声明文件，源码中没有 `@ConfigurationProperties`、`spring.factories` 或 `AutoConfiguration`；连接信息全部通过代码（`addDataSource(...)`）或宿主注入的 `DataSource` 传入。

唯一的「配置面」是向量存储 Provider 的 6 个表单键（`PostgresqlVectorStorageProvider` 公开常量），用于 `toProperties(Map)`：

| 键 | 常量 | 默认值 | 说明 |
|---|---|---|---|
| `tableName` | `KEY_TABLE_NAME` | `vector_store` | 向量表名 |
| `idColumn` | `KEY_ID_COLUMN` | `id` | 标识列名（`VARCHAR(255)` 主键） |
| `vectorColumn` | `KEY_VECTOR_COLUMN` | `embedding` | 向量列名 |
| `ivfflatLists` | `KEY_IVFFLAT_LISTS` | `100` | ivfflat 索引列表数（仅 ivfflat 模式） |
| `hnswM` | `KEY_HNSW_M` | `16` | HNSW 最大度数 M（仅 hnsw 模式） |
| `hnswEfSearch` | `KEY_HNSW_EF_SEARCH` | `40` | HNSW 检索深度 ef_search |

## SPI 扩展点

模块通过 `META-INF/extensions` 注册 5 个扩展点，协议名均为 `postgresql`，宿主用 `ServiceProvider.of(接口.class).getExtension("postgresql")` 加载：

| SPI 接口 | 实现类 | order | 说明 |
|---|---|---|---|
| `com.chua.common.support.lang.datasource.engine.Engine` | `PostgresqlEngine` | — | JDBC 引擎 |
| `com.chua.datasource.support.engine.ReactorEngine` | `PostgresqlReactorEngine` | — | 响应式引擎 |
| `com.chua.common.support.lang.datasource.engine.ddl.DdlProvider` | `PostgresqlDdlProvider` | — | 建库 / 建表 DDL（支持 `postgresql`、`postgresql9`、`postgresql10`） |
| `com.chua.common.support.lang.datasource.flyway.ScriptConverter` | `PostgresqlScriptConverter` | 100 | 迁移脚本方言转换 |
| `com.chua.common.support.vector.VectorStorageProvider` | `PostgresqlVectorStorageProvider` | 60 | pgvector 向量存储工厂 |

扩展点行为要点：

- **DDL**：建库用 `DO $$ ... EXCEPTION WHEN duplicate_database THEN NULL` 保证幂等；删库为 `DROP DATABASE IF EXISTS`；建表为 `CREATE TABLE IF NOT EXISTS`，标识符加双引号（内嵌双引号双写转义），自增主键用 `GENERATED BY DEFAULT AS IDENTITY`，未指定类型的列默认 `VARCHAR(255)`；列注释不并入建表 DDL。
- **脚本转换**：先走父类通用规则（剥 `ENGINE=`、行内 `KEY`、内联 `COMMENT`、定界符、`TEXT` / `DATETIME` / `NOW()` / `IFNULL` 映射），再做 PostgreSQL 特有替换：`DOUBLE`→`DOUBLE PRECISION`、`(VAR)BINARY(n)` / `BLOB`→`BYTEA`、`YEAR`→`SMALLINT`、`MEDIUMINT`→`INTEGER`、`TINYINT`→`SMALLINT`、`REPLACE(UUID(),'-','')`→`replace(gen_random_uuid()::text,'-','')`、裸 `UUID()`→`gen_random_uuid()::text`。`INSERT IGNORE` 剥掉后追加 `ON CONFLICT DO NOTHING`；upsert 片段把 `VALUES(col)` 改写为 `EXCLUDED.col`；`ON DUPLICATE KEY UPDATE` 语句整条跳过（PostgreSQL 需要显式冲突目标，避免生成错误 upsert）。以上经 postgresql-42.7.4 对 PostgreSQL 16.2 实测。
- **元数据**：读取走 `information_schema` 与 `pg_catalog`（`pg_class` / `pg_index` / `pg_trigger` / `pg_proc` / `pg_constraint` 等），schema 过滤统一为 `COALESCE(?, current_schema())`，全部绑定参数；联合索引 / 联合外键用 `unnest(...) WITH ORDINALITY` 展开列序。
- **向量存储**：能力探测以「建表是否成功」为准——先 `CREATE EXTENSION IF NOT EXISTS vector`（失败仅记日志），再尝试建 `vector(dim)` 列的表；成功则距离下推数据库（`<=>` 余弦 / `<->` 欧氏 / `<#>` 负内积）并尝试建 HNSW 索引（`m = hnswM`，`ef_construction = hnswM*2`）；失败则退化为 `double precision[]` 列，检索在 JVM 内精算。`algorithm` 为 `null` 时按余弦处理；自定义算法不建索引、走 JVM 精算。

## 边界与已知限制

- **用户 / 权限 / 全文检索元数据不支持**：`PostgresqlMetaData#user()`、`permission()`、`search()` 直接抛 `UnsupportedOperationException`；全文检索需 tsvector 生成列 + GIN 索引，如有需要请自行实现 `com.chua.common.support.lang.datasource.meta.SearchEngine`。
- **不支持运行期更换数据源**：`setSource` 抛 `UnsupportedOperationException`，数据源在 `addDataSource(...)` 时确定。
- **`ON DUPLICATE KEY UPDATE` 不转换**：此类迁移脚本会被整条跳过，需要 upsert 请改写成 PostgreSQL 的 `INSERT ... ON CONFLICT ...`。
- **响应式是伪响应式**：`PostgresqlReactorEngine` 默认把阻塞 JDBC 包在 boundedElastic 上；只有用 JDBC URL 注册数据源走 R2DBC 才是真非阻塞。
- **物化视图不覆盖**：视图元数据只读 `information_schema.views` 的普通视图，`ViewDef` 也无法区分物化视图。
- **不可见索引显式拒绝**：PostgreSQL 没有不可见索引，`visible(false)` 抛异常而不是静默忽略。
- **内置触发器不暴露**：`tgisinternal` 为真（如外键 RI 触发器）的触发器不会出现在触发器清单里。
- **pgvector 退化路径**：pgvector 不可用时向量列退化为 `double precision[]`，检索由 JVM 全量精算；建表失败会直接抛错，不会静默降级为内存存储。
- **驱动版本**：R2DBC 驱动固定为 `0.9.2.RELEASE`；JDBC 驱动版本由父 pom 统一管理。
